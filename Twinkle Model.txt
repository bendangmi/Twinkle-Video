# 视频生成 API

> 这是一套面向调用方的统一视频任务接口。模型目录、能力限制和价格以接口实时返回为准，调用方不需要为不同模型维护不同的任务状态或下载流程。

## 1. 接入信息

- Base URL：`https://big-model.smart-agi.com`
- 认证：`Authorization: Bearer <API_KEY>`
- 当前 API Key：视频
- 服务状态：可用

所有请求均使用 JSON（下载接口除外）。API Key 只应保存在服务端，不要写入浏览器代码、URL、日志或公开仓库。

## 2. 获取可用视频模型

GET https://big-model.smart-agi.com/v1/videos/models

模型列表只返回当前 API Key 可以使用的模型。创建任务前请读取此接口，并使用响应中的 `id`、`constraints` 和 `pricing` 生成客户端选项。

```bash
curl 'https://big-model.smart-agi.com/v1/videos/models' \
  -H 'Authorization: Bearer YOUR_VIDEO_API_KEY'
```

| 字段 | 说明 |

模型、价格和限制可能动态调整。客户端应缓存目录但定期刷新，不能把示例值当作固定配置。

## 3. 创建视频任务

POST https://big-model.smart-agi.com/v1/videos

```bash
curl -X POST 'https://big-model.smart-agi.com/v1/videos' \
  -H 'Authorization: Bearer YOUR_VIDEO_API_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"model":"Seedance-2.0-Fast-Official-480p","prompt":"电影感镜头，主体清晰，动作连贯","duration":4,"resolution":"480p","aspect_ratio":"21:9","count":1}'
```

### 请求字段

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `model` | string | 是 | `/v1/videos/models` 返回的模型 ID。 |
| `prompt` | string | 是 | 对内容、主体、动作、镜头和风格的描述。 |
| `duration` | integer | 否 | 时长（秒）；必须符合模型目录。也接受 `seconds`、`duration_seconds`。 |
| `count` | integer | 否 | 生成数量，默认 `1`；也接受 `n`。 |
| `resolution` | string | 否 | 例如 `480p`、`720p`、`1080p`；以模型目录为准。 |
| `aspect_ratio` | string | 否 | 例如 `16:9`、`9:16`；以模型目录为准。 |
| `size` | string | 否 | 使用宽高表达尺寸，例如 `1280x720`。 |
| `image_url` / `image_urls` | string / array | 否 | 参考图片。 |
| `video_url` / `video_urls` | string / array | 否 | 参考视频。 |
| `audio_url` / `audio_urls` | string / array | 否 | 参考音频。 |
| `first_frame_url` / `last_frame_url` | string | 否 | 首帧和尾帧图片。 |
| `reference_images` / `reference_videos` / `reference_audios` | array | 否 | 结构化参考素材；每项可使用 URL 或文件标识。 |
| `generate_audio` | boolean | 否 | 是否生成音频，默认由模型决定。 |
| `negative_prompt` | string | 否 | 不希望出现的内容。 |
| `long_term_storage` | boolean | 否 | 请求在任务完成后保留长期副本（需系统开启此能力）。 |

参考素材必须是服务端可读取的地址或符合模型目录要求的文件标识。数量、格式、大小和时长以 `constraints.reference_limits` 及模型目录为准。

### 创建响应

```json
{
  "id": "video_xxx",
  "status": "queued",
  "model": "Seedance-2.0-Fast-Official-480p",
  "created_at": "2026-08-24T12:00:00Z",
  "completed_at": null,
  "error": null
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 任务 ID。后续查询和下载都使用它。 |
| `status` | `submitting`、`queued`、`in_progress`、`completed`、`failed` 或 `unresolved`。 |
| `model` | 实际使用的模型 ID。 |
| `completed_at` | 完成时间；未完成时为 `null`。 |
| `error` | 失败时的 `{ code, message }`。 |

## 4. 查询任务

GET https://big-model.smart-agi.com/v1/videos/{id}

建议从 5 秒开始轮询，并在任务持续处理时逐步增加间隔。不要因为单次请求超时就重新创建任务。

```bash
curl 'https://big-model.smart-agi.com/v1/videos/VIDEO_TASK_ID' \
  -H 'Authorization: Bearer YOUR_VIDEO_API_KEY'
```

| 状态 | 含义 |
| --- | --- |
| `submitting` / `queued` | 任务已接收，等待处理。 |
| `in_progress` | 正在生成。 |
| `completed` | 已完成，可以下载。 |
| `failed` | 任务失败，读取 `error`。 |
| `unresolved` | 长时间未取得最终状态，请人工核查。 |

## 5. 下载结果

GET https://big-model.smart-agi.com/v1/videos/{id}/content

任务完成后使用此接口获取视频二进制。接口保持 API Key 鉴权，不要求调用方处理结果地址。

```bash
curl -L 'https://big-model.smart-agi.com/v1/videos/VIDEO_TASK_ID/content?download=1' \
  -H 'Authorization: Bearer YOUR_VIDEO_API_KEY' \
  -o video.mp4
```

- 普通响应为 `200`，支持 `Range` / `If-Range` 断点续传时可能返回 `206`。
- `download=1` 或 `download=true` 返回下载响应；不传时适合浏览器播放。
- 任务未完成时返回 `409` 和 `video_not_ready`。

## 6. 错误与重试

| HTTP | 常见错误 | 处理建议 |
| ---: | --- | --- |
| `400` | `invalid_request`、`model_not_found`、`invalid_duration`、`invalid_resolution` | 修正请求后重新创建。 |
| `401` | `api_key_required` | 检查 Bearer Token 和 API Key 权限。 |
| `402` | `insufficient_balance` | 补充可用余额后重试。 |
| `404` | `video_not_found` | 检查任务 ID 是否属于当前 API Key。 |
| `409` | `video_not_ready` | 继续查询任务状态。 |
| `413` | `request_too_large` | 减少 Base64 或参考素材，当前请求体上限为 36 MiB。 |
| `429` | `rate_limit_exceeded` | 使用指数退避，不要并行重复创建。 |
| `502` | `video_download_failed` | 稍后重试内容接口。 |
| `503` | `video_generation_disabled`、`video_generation_failed` | 稍后重试或联系系统管理员。 |

错误响应格式：

```json
{
  "error": {
    "type": "invalid_request",
    "message": "Request is invalid"
  }
}
```

## 7. 计费说明

当前文档使用的充值比例为 `1:10`。实际预扣、结算和退款以任务创建后的账单字段为准；客户端不应自行推算最终扣费。
